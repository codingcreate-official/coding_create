Arrays

  • الـ array تركيب في اللغة بينظم قائمة من العناصر وليه syntax خاص للوصول لعناصره.
  • هو ordered list of values، الاسم واحد للـ array كلها وكل قيمة ليها index رقمي.

Method Declaration

  • الـ method بلوك كود (مجموعة statements) بتنفذ مهمة معينة، بنكتبها مرة ونستخدمها كذا مرة (reusability).
  • بتسهل التعديل والـ readability بإضافة أو حذف جزء كود.
  • الـ declaration بيحدد الكود اللي هيتنفذ لما الـ method تتنادى (invoked).
  • لما تتنادى الـ flow بيروح للـ method وينفذ كودها، ولما تخلص يرجع لمكان النداء ويكمل.
  • النداء ممكن يرجّع قيمة أو لأ حسب التعريف.
  • التعريف = method header يليه method body.
int calc(int num1, int num2)
{
  int sum = num1 + num2;
  return sum;
}
  • الـ sum و result بيانات local: بتتعمل كل مرة تتنادى فيها الـ method وبتتمسح لما تخلص.
  • تعبير الـ return لازم يتوافق مع الـ return type.

Parameters و return

  • الاسم في الـ declaration = formal parameter، والقيم وقت النداء = actual parameters وبتتنسخ في الـ formal.
  • مثال: ch = calc(25, count); فالـ 25 و count بيتنسخوا في num1 و num2.
  • الـ return type بيحدد نوع القيمة الراجعة، والـ method اللي مبترجعش قيمة return type بتاعها void.
  • الـ return statement: return expression; والـ expression لازم يطابق الـ return type.

Variable Length Parameter Lists

  • لما method تعالج عدد مختلف من القيم في كل نداء (مثلاً average(42,69,37) و average(35,43,93,23,40,21,75)).
  • الـ overloading عيبه محتاج نسخة لكل عدد، والـ array عيبه لازم نبنيها قبل كل نداء، فـ Java بتوفر varargs.
  • الـ parameters بتتحط أوتوماتيك في array جوه الـ method.
public double average(int ... list) {
  double result = 0.0;
  if (list.length != 0) {
    int sum = 0;
    for (int num : list) sum += num;
    result = (double) sum / list.length;
  }
  return result;
}
  • تصحيح السلايد كاتب (double) num / list.length والصح sum (الـ num بره الـ loop مش متعرف).
  • النوع ممكن primitive أو object: printGrades(Grade ... grades).
  • الـ varargs لازم تكون آخر parameter، ومينفعش method فيها مجموعتين varargs.
  • الـ method ممكن تاخد parameters تانية قبلها، والـ constructors كمان تقبل varargs.

أسس كتابة الـ Methods

  • Modularity: اتبع Single Responsibility Principle، يعني method واحدة لمسؤولية واحدة، ولو بقت معقدة قسمها لـ methods أصغر.
  • Input Validation: اتأكد من الـ inputs، شيك على null والقيم الخارج المدى وتعامل معاها بهدوء، بـ conditionals أو بـ throw exceptions.
  • Code Reusability: صمم methods تتستخدم في سياقات مختلفة (generic / parameterized).
  • Error Handling: حدد هتعمل throw exception ولا ترجع error codes ولا تعالج جوه الـ method برسايل مناسبة.
  • Code Readability: كود نظيف، أسماء variables و methods معبرة، تنسيق ثابت، وتعليقات توضح الغرض.

Guidelines to OO Design

  • Understand the requirements: افهم المتطلبات والأهداف، وحدد الـ functionalities وتفاعلات المستخدم وقيود النظام.
  • Identify objects & responsibilities: حدد الـ objects الرئيسية وسلوك كل واحد والعمليات اللي يحتاجها.
  • Define relationships: associations, aggregations, compositions, generalizations (inheritance) وهي بتحدد تعاون الـ objects.
  • Create class diagrams: بـ UML (classes، relationships، multiplicity) وحسّنها مع تطور التصميم.
  • Consider trade-offs: بين performance, maintainability, scalability، وأثر القرارات على الذاكرة وتعقيد الكود، وحقق توازن.
  • Validate the design: راجعه مع stakeholders وخبراء ومطورين وخد feedback بدري.
  • Document the design: قرارات وأسباب وعناصر رئيسية، مع diagrams وتعليقات.
  • General: الـ OO design عملية iterative، خليه مرن للتغييرات المستقبلية وراجعه باستمرار للحفاظ على كود عالي الجودة وقابل للتوسع والصيانة.

مثال Animal / Dog / Cat

class Animal {
  private String name;
  public Animal(String name) { this.name = name; }
  public String getName() { return name; }
  public void makeSound() { System.out.println(name + " makes a generic animal sound."); }
}
class Dog extends Animal {
  public Dog(String name) { super(name); }
  public void makeSound() { System.out.println(getName() + " barks: Woof! Woof!"); }
  public void fetch() { System.out.println(getName() + " is fetching the ball!"); }
}
class Cat extends Animal {
  public Cat(String name) { super(name); }
  public void makeSound() { System.out.println(getName() + " meows: Meow! Meow!"); }
}
Animal myDog = new Dog("Buddy");        // polymorphic reference
Animal myCat = new Cat("Whiskers");
Animal genericAnimal = new Animal("Unknown");
myDog.makeSound();   // Buddy barks: Woof! Woof!
myCat.makeSound();   // Whiskers meows: Meow! Meow!
genericAnimal.makeSound();  // Unknown makes a generic animal sound.
Animal[] shelter = { new Dog("Rex"), new Cat("Luna"), new Animal("Creature") };
for (Animal animal : shelter) animal.makeSound();
if (myDog instanceof Dog) {    // downcasting
  Dog actualDog = (Dog) myDog;
  actualDog.fetch();   // Buddy is fetching the ball!
}

Static Members

  • Java بتدعم methods و variables global بتتنادى من غير object، اسمهم static members وبتتعرف بكلمة static.
  • مفيدة لما نحتاج variable مشترك بين كل instances الكلاس (زي عداد عدد الـ objects).
  • Java بتعمل نسخة واحدة بس من الـ static variable وتتستخدم حتى لو الكلاس عمره ما اتعمل منه object.
  • الوصول بالاسم: ClassName.StaticVarName مثل nCircles = Circle.numCircles;
public class Circle {
  private static int numCircles = 0;   // one per class
  private double x, y, r;              // one per object
  Circle(double x, double y, double r) {
    this.x = x;  this.y = y;  this.r = r;
    numCircles++;
  }
}
Circle circleA = new Circle(10, 12, 20);  // numCircles = 1
Circle circleB = new Circle(5, 3, 10);    // numCircles = 2

Static Methods

  • بتتنادى من غير object (زي main)، وغالباً بتجمع دوال مكتبة مش معتمدة على data members الكلاس (زي Math).
class Comparator {
  public static int max(int a, int b) { if (a > b) return a; else return b; }

    if (a.compareTo(b) > 0) return a; else return b;

}

  • الـ this و super مينفعش في static context.

  • إخفاء تفاصيل التنفيذ وإظهار الوظيفة بس للمستخدم، يعني نركز على الـ object بيعمل إيه مش بيعمله إزاي.

Abstract Classes

  • بتتعرف بـ abstract، ممكن فيها abstract و non-abstract methods، وممكن فيها constructors و static methods و final method.
  • مينفعش تتعمل منها objects، وكلاس conceptual بيدي root مشترك لمجموعة classes.
  • أي كلاس بيعمل extends لها لازم يعمل override لكل abstract methods بتاعتها، وهي ممكن تحتوي 0 أو أكتر.
  • الـ final مينفع يتورث، وأحياناً عايزين الخصائص دايماً تتورث وتتستخدم فنعمل abstract classes.
  • لو الكلاس فيه method abstract واحدة أو أكتر لازم يتعرف abstract (وبيبقى abstract تلقائياً).
  • كلاس معرّف abstract حتى من غير abstract methods برضو ميتعملش منه object.
  • الـ subclass ينفع يتعمل منه object لو عمل override لكل الـ abstract methods، وإلا يبقى هو نفسه abstract.
  • مينفعش نعرّف abstract constructors أو abstract static methods.
abstract class ClassName {
  abstract Type MethodName1();     // no body
  Type Method2() { /* method body */ }
}
public abstract class Shape {
  private String name;
  public Shape() { this.name = "Unknown shape"; }
  public Shape(String name) { this.name = name; }
  public abstract void draw();
  public abstract double getArea();
  public abstract double getPerimeter();
}
public class Rectangle extends Shape {
  private double width, height;
  public Rectangle(double width, double height) {
    super("Rectangle");  this.width = width;  this.height = height;
  }
  public void draw() { System.out.println("Drawing a rectangle..."); }
  public double getArea() { return width * height; }
  public double getPerimeter() { return 2.0 * (width + height); }
}
public class Circle extends Shape {
  private double radius;
  public Circle(double radius) { super("Circle"); this.radius = radius; }
  public void draw() { System.out.println("Drawing a circle..."); }
  public double getArea() { return Math.PI * radius * radius; }
  public double getPerimeter() { return 2.0 * Math.PI * radius; }
}
  • السؤال: Shape s = new Shape(); valid؟ No، illegal لأن Shape abstract.
  • Summary: لو مش عايز الكلاس يتورث اعمله final (للـ classes والـ methods). ولو عايزه يتورث ويتستخدم اعمله abstract (للـ classes والـ methods)، والـ subclasses لازم تنفذ الـ abstract methods وإلا ميتعملش منها objects.

Interface

  • طريقة تانية لتحقيق الـ abstraction، ومينفعش تعمل منها objects، والكلاسات implement الـ interfaces.
  • عند التنفيذ لازم تعمل override لكل methods الـ interface، والـ interface مفيهوش constructor.
  • الـ multiple inheritance ممكن بالـ interfaces لأن الكلاس يقدر يعمل implement لأكتر من interface.
  • الـ scope: public أو package-level (default)، وبتتعرف بكلمة interface، وتعريفها abstract ضمنياً.
  • الأعضاء: constant fields، وabstract و static و default methods، وstatic types (nested interfaces و classes)، ومفيهاش instance أو class variables قابلة للتغيير.
  • زي class لكن: كلمة interface، كل methods من غير body، مفيش instance variables، ومينفعش new Trainable().
  • هي زي contract أو protocol أو role، والكود المكتوب لنوع interface بيشتغل مع أي object بينفذها.
  • Interface يقدر يعمل extends لـ interface تانية وبيرث كل أعضائها: interface InterfaceName2 extends InterfaceName1 { ... }

Data members و Methods

  • كل fields الـ interface implicitly public static final ولازم تتهيأ وقت التعريف، وتتوصل بـ InterfaceName.FIELD (مثل Choices.YES).
  • الـ methods abstract و public افتراضياً، وغياب static و default بيخليها abstract.
  • من Java 8: static methods في الـ interface (وهي public ضمنياً).
  • الـ default method بتدي implementation افتراضي للكلاسات اللي بتنفذ الـ interface، ومش مجبرة تعمل لها override (لكن تقدر).
interface SaySomething {
  default void defaultMsg() { System.out.println("Working..."); }  // Default
  void sayMsg(String msg);                                         // Abstract
}
public class Person implements SaySomething {
  public void sayMsg(String msg) { System.out.println(msg); }
  public static void main(String[] args) {
    Person p = new Person();
    p.defaultMsg();  p.sayMsg("Working hard...");
  }
}
  • الكلاس ممكن ينفذ interface-ين (SaySomething, DoSomething) وكل واحدة فيها default method وabstract method، وممكن نعمل override للـ default.

Identify the problems (Circle و B)

  • الـ constructor: radius = radius; غلط، والصح this.radius = radius;
  • في B: Circle(radius); غلط، والصح super(radius);
  • length = length; والصح this.length = length;
  • getArea() في B بتنادي نفسها (recursion لا نهائي)، والصح super.getArea() * length.
  • كمان radius private في Circle فـ B متقدرش توصل له مباشرة.
